# Phase 0: secure the work, make builds safe

- **Dates:** 2 to 3 October 2026
- **Plan:** tasks 0.1 to 0.7; findings F16, F19, F20; decisions D3, D6, D7
- **Commits:** `859243e` (snapshot), `d811521` (build system), `38534c1` (CI)
- **Written:** reconstructed on 5 October 2026 from the plan's results and
  the commit messages

## Goal

Nothing can be lost, and a build cannot overload the PC.

## What was done

- **0.1 Commit and push.** Five months of work went in as one commit on a new
  branch `core-revision`, not the three the plan proposed: the intermediate
  states could not have been rebuilt and checked, and a commit nobody can
  build is no record. Textbook PDFs stay out of the public repository
  (`.gitignore`).
- **0.2 The build limit in the build system.** The rule "never more than one
  compiler at a time" had lived only in the assistant's memory. It became a
  Ninja job pool (`MBD_COMPILE_JOBS`, default 1), so a plain `cmake --build`
  obeys it; `CMakePresets.json` and `scripts/build.ps1` give one way to
  build.
- **0.3 Measure, then relax.** One compiler needed 1.6 GB without help, 1.1 GB
  with the shared precompiled header, 1.7 GB for the header itself. Memory
  alone would allow about six compilers; the default stays at one until the
  cause of the two restarts is known (decision D9).
- **0.4 Cut compile cost.** One precompiled header shared by all test
  executables: a test file went from 92 s to 23 s, the vehicle tests from 16
  to 7.5 minutes, a full rebuild from about an hour to 21 minutes. The
  logging helpers that pull in spdlog moved out of `core.hpp`.
- **0.5 Meaningful CI.** RelWithDebInfo through the same preset, every
  dependency pinned to a hash, `/W4`, and a Linux job with GCC and the address
  and undefined-behaviour sanitizers, made blocking after its first pass.
- **0.6 Tidy.** A README; the stray `};` and the misplaced `<cassert>` (F16)
  fixed. The new warning level found seven unused variables in tests.
- **0.7 Conventions.** `docs/conventions.md`: frames, units, signs, naming.

## What went wrong, and how it was found

**Header changes stopped triggering rebuilds, silently.** Visual Studio here
has a Spanish interface, so the compiler's notes on included files are
translated ("Nota: inclusión del archivo:"), and Ninja recognises them by a
prefix recorded when CMake configures. Configuring under one console code page
and building under another made the prefix stop matching: Ninja then saw no
header dependencies at all, and edited headers did not rebuild anything. The
build script now pins the code page and configures again when it changes
(README, "Non-English Visual Studio").

## Measurements

Compile times and peak memory per compiler, in the README's build-limits
section (later updated by task 2.8).

## Lessons

- Rules that protect the machine belong in the build system, not in anyone's
  memory.
- A build that silently skips work is worse than one that fails.

## For the book

- The code-page story is a good example of a failure that produces no error:
  how it was noticed, why it happened, why the fix lives in a script.
- The cost model of C++ compilation (parsing shared headers again in every
  file) explains Phase 0's precompiled header and Phase 2's compiled library.
